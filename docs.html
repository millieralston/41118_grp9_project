Setup

1 — Activate the virtual environment

source venv/bin/activate

2 — Install dependencies

pip install -r requirements.txt

Or install core packages directly:

pip install gymnasium pybullet stable-baselines3 opencv-python \
    ultralytics torch torchvision tensorboard matplotlib

Note on ultralytics

ultralytics is required for YOLO annotations in the demo and for training the detector. The PPO training pipeline and demo run without it — raw camera frames are shown instead of annotated boxes.

Training the PPO Agent

python train.py --timesteps 120000

This script:

  • Creates HuskyChaserEnv in DIRECT mode (headless) for fast training
  • Uses Stable Baselines3 PPO with an MLP policy (lr=3e-4, n_steps=512, batch=64)
  • Saves step checkpoints every 10,000 timesteps to checkpoints/
  • Logs task-specific metrics — distance, capture rate, collisions — to TensorBoard
  • Writes the final model to husky_chaser_ppo_final.zip

Resume from checkpoint

python train.py --resume husky_chaser_ppo_final.zip

Force fresh training

python train.py --fresh-start --timesteps 120000

PyBullet parallelism

The environment uses PyBullet's global API, so n_envs is kept at 1. Running multiple environments in parallel requires binding each PyBullet call to a separate physicsClientId.

Running the Demo

python demo.py --model husky_chaser_ppo_final --episodes 5

Record to MP4

python demo.py --model husky_chaser_ppo_final --episodes 5 \
    --record --out recordings/demo_run.mp4

If YOLO weights are present at runs/detect/yolo_training/runner_detector_v2/weights/best.pt, the recording will include annotated detection boxes drawn on the chaser's camera feed. Otherwise the raw camera image is used as a fallback.

YOLO Dataset & Detection

Step 1 — Collect labelled frames from simulation

python collect_yolo_dataset.py

Captures up to 3,500 labelled camera frames from the chaser's onboard 640×480 camera. Ground-truth bounding boxes are derived automatically from PyBullet's segmentation mask. A two-stage quality filter rejects frames where the runner covers fewer than 200 pixels or where the visibility ratio (visible pixels ÷ bounding box area) falls below 0.5.

Step 2 — Split into train / val

python split_dataset.py

Step 3 — Fine-tune YOLOv11n

python train_yolo.py

Fine-tunes yolo11n.pt on the collected dataset for up to 100 epochs with early stopping (patience=20). Weights are saved to yolo_training/runner_detector_v2/weights/best.pt.

Step 4 — Test live inference

python yolo_live_test.py

Detection performance

The trained model achieved >99% precision and recall on the validation set, with mAP50-95 of 0.975. False negatives were predominantly cases of heavy occlusion behind obstacles.

Reward Function

The per-step reward combines a primary pursuit signal with several safety penalties and a large terminal capture bonus. All values below are in reward units.

SignalValueNotes
Catch bonus +800 Contact with runner or distance ≤ 2.3 m — terminates episode
Closing distance +60 × progress Progress = reduction in chaser–runner distance this step
Moving away −12 × |loss| Applied when distance increases
Close-range bonus +1.8 × (5 − dist) Active within 5 m — rewards sustained pressure on runner
Obstacle contact −3.0 to −4.5 Grows by 0.15 per consecutive contact step (up to 10 steps)
Wall contact −4.0 Per step in contact with arena fence
Wall boundary crossed −5.0 Chaser enters the 1 m inner margin of the 20×20 arena
Stuck terminal −35 80 consecutive steps where forward action > 0.4 but position barely changes
Obstacle contact terminal −35 45 consecutive contact steps with an obstacle
Flip terminal −100 Roll or pitch exceeds 1.0 rad
Step cost −0.01 to −0.025 Base −0.01 plus a time-increasing term up to −0.025 by episode end

Observation Vector (8-D)

The PPO MLP receives an 8-dimensional vector in the chaser's local frame at every step. Relative coordinates make the policy learn "where is the target relative to me?" rather than memorising absolute arena positions.

IndexChannelDescription
0runner_xRunner position ahead/behind chaser (local x)
1runner_yRunner lateral offset from chaser (local y)
2–3obs1_x, obs1_yNearest obstacle in chaser frame
4–5obs2_x, obs2_ySecond-nearest obstacle
6–7obs3_x, obs3_yThird-nearest obstacle (zero-padded if < 3 present)

TensorBoard Logs

tensorboard --logdir ./husky_ppo_logs/

Then open http://localhost:6006 in your browser.

The custom TaskMetricsCallback in train.py logs the following beyond standard SB3 metrics:

Continuous (per rollout)

  • task/distance_to_runner
  • task/chaser_movement
  • task/min_obstacle_distance
  • task/wall_clearance
  • task/near_target

Episode flags (per episode)

  • task_episode/caught
  • task_episode/is_success
  • task_episode/collision
  • task_episode/fell_over
  • task_episode/ended_stuck
  • task_episode/truncated

GUI shortcut

The Open TensorBoard button in gui.py launches TensorBoard automatically and populates the in-app TF Log Viewer with the same data.
